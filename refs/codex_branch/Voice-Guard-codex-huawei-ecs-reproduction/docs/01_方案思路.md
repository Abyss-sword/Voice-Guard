# Voice Guard 复现与探索 —— 初步方案思路

> 论文：*Voice Guard: Protecting Voice Privacy with Strong and Imperceptible Adversarial Perturbation in the Time Domain*
> Jingyang Li, Dengpan Ye, Long Tang, Chuanxi Chen, Shengshan Hu
> IJCAI 2023, Main Track, pp. 4812–4820　|　选题编号 **A036**　|　方向：Audio / 音频主动防御

---

## 0. 一句话结论

这是一个「**小代码 + 大工程**」的选题：论文核心只有 3 段逻辑（可微特征 → 时域扰动 → 掩蔽阈值约束），但官方仓库只放了 3 个 `.py` 文件（`attack_utils.py` / `data_utils.py` / `generate_masking_threshold.py`），**不含任何权重、训练脚本和 VC/ASV/MOS 推理管线**。真正的工作量在于把上游 [Attack-VC](https://github.com/cyhuang-tw/attack-vc) 的整套评测骨架（AdaIN-VC + Griffin-Lim + 说话人判别器）重新搭起来，再把 Voice Guard 的两个创新点接进去。

因此策略是：**先立骨架跑通基线（attack-vc 三种频域攻击），再换时域 + 加心理声学，最后用"真实信道压缩"做加分项**。骨架一旦跑通，后面每一步都是可控增量的实验，而不是一次性赌运气。

## 1. 论文到底做了什么（复现对象的精确定义）

### 1.1 威胁模型

篡改者从公开网络收集目标说话人 X 的音频 $\hat{x}$，配合任意内容音频 $\hat{t}$，用零样本 VC 模型 $F(\cdot,\cdot)$ 合成"X 的声音说 $\hat{t}$ 的话"。主动防御＝在 $\hat{x}$ 里预先注入人耳不可感知的扰动 $\hat{\delta}$，使

$$ASV\big(F(\hat{x}+\hat{\delta},\ \hat{t})\big) \neq X$$

### 1.2 两个创新点

**创新点 1：把扰动从频域搬到**时域**（避免跨域损耗）。**
已有工作（attack-vc 的 emb/fb/e2e）在 mel 频谱上加噪声，必须经声码器上采样回波形，这一步"有损"，会削弱扰动。Voice Guard 直接优化 1×L 的时域波形 $\hat{\delta}=\epsilon\tanh(\hat{w})$。难点是 librosa 的 mel 提取不可导，所以**自己用 PyTorch 重写可微 mel 提取器 $H(\cdot)$**，靠链式法则 $\partial F/\partial\hat{\delta} = \partial F/\partial H \cdot \partial H/\partial\hat{\delta}$ 把梯度传回波形层。

**创新点 2：引入心理声学掩蔽模型（首次用于 VC 防御）。**
时域加噪＝加更多噪声源，MCD 变大、更容易被听出来。于是用**掩蔽效应**：用原始音频的高能量成分"盖住"低能量扰动。计算归一化 PSD → 识别掩蔽者（局部极大 + 高于绝对听阈 ATH + 0.5 Bark 内最强）→ 双斜率扩散函数算个体掩蔽阈 → 对数域叠加得全局掩蔽阈 $\theta_x$。

### 1.3 核心公式（复现必须逐条对上）

| 编号 | 内容 | 关键点 |
|---|---|---|
| Eq.3 | $L_{vc}=L(E_s(H(\hat{x}+\hat{\delta})),E_s(H(\hat{y})))-\lambda L(E_s(H(\hat{x}+\hat{\delta})),E_s(H(\hat{x})))$ | 用的是 **emb（嵌入）防御**：不经过解码器/声码器，只打说话人编码器 → 效率最高 |
| Eq.4–6 | $P_x(k)=10\log_{10}\lvert\frac{1}{N}s_x(k)\rvert^2$；$\bar P_x=96-\max P_x+P_x$；$\theta_x=P(\bar P_x)$ | 归一化 PSD 的 $1/N$ 常数、96 dB 基准都要和 numpy 版严格一致 |
| Eq.7 | $L_\theta=\mathbb{E}_k\max\{\bar P_\delta(k)-\theta_x(k)\}$ | hinge：只惩罚"超出掩蔽阈"的部分 |
| Eq.8 | $\min_{\hat w} L=L_{vc}+\alpha L_\theta$，s.t. $\hat\delta=\epsilon\tanh(\hat w)$ | $\alpha$ 自适应：在**能防御成功**的前提下取最大（噪声藏得最深） |

### 1.4 算法流程（Algorithm 1）

```
δ ~ N(0,1)                                    # 随机初始化
for t1 in T1:  δ ← δ - lr1·∇L_vc               # 阶段1：只求"强"，3000 步, Adam 1e-3
for f in F:                                    # 阶段2：加"隐"，α 二分搜索
    for t2 in T2: δ ← δ - lr2·∇(L_vc + α·L_θ)  # 1500 步
    α ← BinarySearch(是否仍防御成功)
return δ
```

### 1.5 评测体系（论文的第三个贡献，容易被忽略但占分）

论文首次把"破坏力"和"隐蔽性"合成为一个判定：

$$F_{imp}: ASV(W_{df})=X \wedge MOS(W_{df})\ge MOS_{th} \wedge ASR(W_{df})\ge ASR_{th}$$
$$F_{str}: ASV(W_{vc})\neq X \vee MOS(W_{vc})<MOS_{th} \vee ASR(W_{vc})<ASR_{th}$$
$$F_d = F_{imp} \wedge F_{str},\qquad DAcc = N_s/N$$

即：**防御后的音频还得像 X 说的、还能听懂**（否则等于把人声毁了，属于失败），**而转换后的音频必须不像 X**。阈值取 $MOS_{th}=3$、$ASR_{th}=10\%$（Sec 5.4）。

指标：Defend / MCD / ASV acc / MOS(MOSNet) / CER·WER(Whisper)，按 MCD 区间分桶统计。

### 1.6 论文基线数字（我们的复现靶子）

| 模型 | 方法 | Defend | MCD | ASV | MOS |
|---|---|---|---|---|---|
| AdaIN-VC 白盒 | emb / fb / e2e | 33.3 / 44.2 / 48.2% | 3.70 / 3.26 / 3.15 | 76.7→19.0 / 89.9→26.9 / 83.7→28.8 | 3.08→2.84 … |
| AdaIN-VC 白盒 | **VG w/o P** | 75.90% | 5.86 | 99.2→10.4 | 3.71→3.14 |
| AdaIN-VC 白盒 | **VG（完整）** | **80.06%** | 4.34 | 99.2→13.6 | 4.07→3.27 |

Tab.1（只看说话人身份）：AdaIN-VC 上 VG 86.40%，VQMIVC 上 94.44%。**"VG w/o P" 这一行是调试的黄金标尺**：先把 75.90% 打出来，再加掩蔽模型冲 80%。

## 2. 复现边界：做什么、不做什么

选题表备注写了两条约束，直接决定范围：

> 「原表未提供可核验的 GPU、最低显存及耗时数值；本次未运行或训练。资源不计入四维难度总分。」
> 「复现路径：**原文音频任务**；不要求 TFG 实验」

解读：① 论文本身没报 GPU/显存/耗时，资源不计入难度分 → 我们**不承担"资源核验"义务**，但顺手在 README 里记录仍可加分。② "原文音频任务"＝按论文原文的音频任务（零样本 VC 主动防御）复现，**不是简化成 ASR**。③ TFG 实验按备注跳过。

据此划定：

**必做（对应"核心方法正确复现 25 分"）**
1. 可微 mel 提取器 $H$：preemph → STFT → mel 滤波 → $20\log_{10}$ → clip 归一化，**与 `file2mel()` 数值对齐（max abs err < 1e-5）**
2. 时域参数化 + emb 损失（Eq.3），least-likely 目标 $\hat{y}$ 的选取
3. 掩蔽阈值 $\theta_x$（Appendix A 三步，numpy 一次性算好）
4. 联合损失 Eq.8 + Algorithm 1 两阶段 + $\alpha$ 二分
5. 防御判定 Eq.9–11 + 五指标（MCD/ASV/MOS/CER/WER）

**可裁剪**
- 训练：一律不训练，只用官方预训练权重（AdaIN-VC / VQMIVC）
- **TFG 相关实验**：按备注不做。TFG 在论文正文中无对应术语（已全文检索），是选题表自带的裁剪标记；我按"不要求做时域↔频域/跨域互转对照"处理——即便如此，emb/fb/e2e 三基线本身就是频域方法，保留它们做对比即可，不额外增加工作量
- 全量 2000 条：改为分层抽样（见 §5），并显式声明"抽样"而非"全量"

**资源核验表（可选，非评分项）**——备注明确"资源不计入难度总分"，故降级为加分材料，只在 README 里顺带记录：
| 项 | 记录方式 |
|---|---|
| GPU 型号 | `nvidia-smi` 截图 + 型号写进报告 |
| 最低显存 | 峰值 `torch.cuda.max_memory_allocated()`，扫 batch=1 时不同音频长度 |
| 单条耗时 | 3000+1500 步 × 二分轮次的 wall-clock，分长度档（2s/4s/8s） |

## 3. 技术难点与对策（这是能不能按时交的关键）

| # | 坑 | 现象 | 对策 |
|---|---|---|---|
| 1 | **`librosa.effects.trim` 不可导且会改变长度** | 梯度断了，或 δ 与波形错位 | 先 trim 一次、冻结裁剪区间，只在切片上优化；输出时贴回原位置 |
| 2 | **$20\log_{10}(\max(1\text{e-}5,\text{mel}))$ 在低能量帧梯度爆炸** | loss 变 NaN、δ 溢出 ε | `clamp` + 训练早期对低能量帧做梯度掩码；ε 用 tanh 硬约束 |
| 3 | **掩蔽阈值的 numpy 版与 torch 版 PSD 归一化不一致** | hinge 永远为 0（等于没加约束）或恒正（等于没优化） | 专门写单测：同一条音频，两条路径的 $P_x$、$\theta_x$ 逐频点比对，误差 < 1e-4 |
| 4 | **$\theta_x$ 是在"干净音频"上算的，但损失里比较的是扰动的 PSD** | 频点含义/帧数不匹配 | 统一 STFT 参数（n_fft/hop/win），帧对齐后逐帧逐频做 hinge，再对帧取平均 |
| 5 | **显存**：δ 长度 = 整段波形，Adam 有 2 阶矩 | 8 GB 卡跑 8s 音频 OOM | 单条串行 + 梯度检查点；长音频按能量分段保护再拼接（并在报告里说明拼接处的影响） |
| 6 | **端点/静音段的掩蔽阈极低** | 噪声在停顿处"露出来"，MOS 掉、听感有嘶声 | 论文未处理 → **这正好是加分项的入口**（见 §6） |
| 7 | **权重下载**（AdaIN-VC 在 Google Drive） | 拿不到 checkpoint 全盘停摆 | 先试 Google Drive 直连 / hf-mirror / ghproxy 镜像；再不行用 attack-vc 作者改过的 config 复现短训（VCTK 单卡数小时） |
| 8 | **GE2E 说话人判别器权重缺失** | 算不出 ASV acc，防御率无从判定 | 备选 speechbrain ECAPA-TDNN（VCTK 上直接用或微调）；报告中说明"绝对值和论文不可比、相对趋势可比" |
| 9 | **"防御成功"依赖 ASV，而 ASV 本身有误差** | 成功率抖动大，表格不稳定 | 固定随机种子、固定注册库、报 3 次重复的均值±方差；MCD 分桶（论文 Fig.3 的做法） |

## 5. 实验设计（对应"实验结果验证 10"）

### 5.1 数据

CSTR VCTK，20 说话人 × 100 条为论文设定。我们抽样为：
- **主表**：10 说话人 × 5 条 = 50 条（AdaIN-VC 白盒）
- **扩展**：再加 50 条跑 VQMIVC 白盒 + 双向黑盒迁移
- **消融**：VG / VG w/o P / emb / fb / e2e × 50 条（emb/fb/e2e 复用同一骨架，成本很低，能直接对上 Tab.2）

理由：论文的结论是**趋势性**的（VG ≫ 基线，且随 MCD 单调上升），50 条足以复现趋势与量级，全量 2000 条在 12.22 前不现实。报告里明确写"抽样复现，置信区间 ±x%"，比假装全量更安全。

### 5.2 阶梯验证（防止"跑出来但不知道对不对"）

```
Step 0  ε=0，不做任何攻击        → 防御率必须 ≈ 0%（验证管线本身无副作用）
Step 1  只加随机噪声              → 防御率应该很低（证明"不是随便加噪就有用"）
Step 2  VG w/o P（纯时域 emb）    → 目标 75.90% ± 5%
Step 3  VG 完整（+掩蔽 +α 二分）  → 目标 80.06% ± 5%，且 MOS 高于 Step 2
Step 4  MCD 分桶曲线              → 复现 Fig.3 的"只升不降"形态
```

每一阶梯都是一个可交付的中间结论，即使最终数字差一点，报告也站得住。

## 6. 加分项设计（最高 +15，性价比最高的一块）

课件给的四级台阶（发现 3 / 验证 4 / 机理 3 / 方案 5）我打算打包成一个故事：

### 6.1 发现的问题

论文全程在**干净的数字音频**上验证。但真实分发必然经过平台二次处理：微信语音（AMR-NB / 低码率 AAC）、抖音/视频号（AAC 128k 左右）、电话信道（8 kHz + G.711 μ-law）、平台响度归一化。**这些处理恰好会摧毁 Voice Guard 赖以生存的两件事**：

- 时域扰动的高频成分 → 8 kHz 重采样直接切掉 4 kHz 以上
- 掩蔽噪声的能量被刻意压在**掩蔽阈之下**（＝低幅值）→ 有损编码器的量化噪声底正好在同一量级，会被当冗余丢掉

### 6.2 实验证明（控制变量）

`clean → 防御 → 施加信道 C → VC → ASV/MOS/WER`，C 取
`{mp3 128/64/32k, aac 128/64k, opus 24k, resample 8k, G.711, +响度归一化, +房间混响(可选)}`，
每条件 50 条 × 3 seed，输出**防御成功率随码率衰减曲线**。预期：干净条件 ~80%，32k mp3 后掉到 20–40%，8 kHz 后接近随机。

### 6.3 机理

画三张图把因果链钉死：
1. 信道前后 δ 的**频带能量分布**（哪一段被杀）
2. δ 的 PSD / 编码器量化噪声底 / 掩蔽阈 三线同图（"藏得太好反而最先被丢"）
3. 扰动存活率 vs 防御成功率的散点 + 拟合（给出"存活阈值"）

### 6.4 改进方案

**EOT（Expectation Over Transformation）稳健扰动**：训练 δ 时每步随机采样一条**可微信道**（可微重采样/低通 + 量化噪声代理 + 随机增益），对期望损失求梯度；同时把掩蔽约束改成"码率感知"——在编码器保留的频带内重新分配扰动能量。对照组：`VG` vs `VG+EOT` 在同一批信道上比成功率。目标：32k mp3 条件下从 ~30% 提到 ~55%。

即使改进只能提 10 个点，"问题—验证—机理"三项已经稳拿 10 分，方案项是额外收益。

### 10.2 RTX 4060 8 GB 的显存设计

8 GB 是硬约束，**不能把 AdaIN-VC + VQMIVC + GE2E + MOSNet + Whisper 同时常驻**。设计原则：

1. **进程级隔离**：VC 攻击（AdaIN-VC + H + 说话人编码器）一个进程；VQMIVC 另一个；ASV/MOS/WER 评测走独立进程、推理完即卸载（`torch.cuda.empty_cache()`）。
2. **δ 优化**：batch=1，δ 长度 = 整段波形（3–5 s ≈ 48k–80k float），显存占用主要是 VC 模型前向/反向 + H 的 STFT。AdaIN-VC 很小（~20 M 参数），单条 8 GB 足够；**长音频按能量分段保护再拼接**，每段 ≤ 4 s。
3. **评测模型降级**：Whisper 跑 WER 用 `base`/`small`（CPU 亦可，只影响速度不影响数值）；MOSNet 很小；说话人判别器若用 speechbrain ECAPA 则单独进程加载。
4. **峰值显存记录**（可选加分材料）：用 `torch.cuda.max_memory_allocated()` 按音频长度分档记录，写进 README。
5. **华为云**：训练/大规模复现可临时用 ModelArts 的 T4/V100（比本地 8 GB 宽裕），本地 4060 负责开发与单条验证。

### 10.3 关键发现：官方仓库是"残缺开源"，工作量被低估了

已逐行核对 [Voice-Guard 官方仓库](https://github.com/WHUB401/Voice-Guard)（只有 3 个文件），确认它**无法直接运行**：

- `attack_utils.py` 里 `from asr_model.find_most_unlikely_speaker import speaker_name` → **`asr_model/` 目录根本没发布**（说话人分类器 + 注册库 + "最不像"目标选择全靠它）；
- `attack_utils.py` 里 `from data_utils import Transform` → **`Transform` 类在 `data_utils.py` 里也不存在**（它做"扰动 PSD 的可微计算 + 归一化"，是 Eq.7 的核心，必须自己实现）；
- 说话人嵌入查询依赖 `your-speaker_encoder_embedding_dict-path`（一个 .npy 字典），同样未发布。

→ 这正好坐实了选题的**非开源性质**：我们不是"抄一份代码跑"，而是要补全 `Transform`、`asr_model`（说话人判别 + 嵌入库 + least-likely 选取）、`models.py`（AdaInVC，可从 attack-vc 取）三大缺口。按课件规则，非开源按工作量给分，这对我们是加分而非减分。

### 10.4 官方代码与论文的几处必须照抄的细节（已录下，避免踩坑）

- `adv_inp = vc_tgt + 2 * eps * tanh(ptb)`：代码里扰动幅值系数是 **2·ε**（论文写 ε·tanh(w)），复现以代码为准。
- stage1 损失 `loss_emb = MSE(adv_emb, tgt_emb) − 0.1·MSE(adv_emb, org_emb)`（λ=0.1），stage2 再加 `c·mean(ReLU(psd_delta − θx))`。
- `c`（=论文 α）**8 轮二分**：初始 1.0，成功则乘 2、失败则与上一次成功值折半。
- `wav2mel_tensor` 的关键点：`torch.stft(center=True, pad_mode='reflect', return_complex=False)` 后 `sqrt(sum(real²+imag²))` 与 librosa `np.abs(stft)` 对齐；`20·log10(max(1e-5, mel))` 后 `clip((mel-ref_db+max_db)/max_db, 1e-8, 1)`，**再做 (mel−mean)/std 归一化**。
- `file2wav_mask`：`librosa.load → trim → clip(-1,1)` 先做一次（numpy、不可导），**之后 H 在已裁剪的波形上纯可微** → 解决了我 §3 表里的 trim 断梯度问题。
- 掩蔽阈：`compute_PSD_matrix` 用 `sqrt(8/3)·STFT`、`z=|win/win_length|`、`psd=10·log10(z²+1e-19)`、`PSD=96−max+psd`，并返回 `psd_max=max(z²)`（线性）；`Transform` 必须用**原始音频的 `psd_max`** 去归一化扰动 PSD，才能与 θx 同尺度比较——这是我补全 `Transform` 时的关键实现点。
- 注意：AdaIN-VC 官方 `preprocess/vctk.config` 写的是 **24 kHz**（`sample_rate=24000`）；attack-vc 的 checkpoint 是"稍改过的 config"，**实际采样率/n_fft/hop/n_mels 要以下载到的 `config.yaml` + `attr.pkl` 为准**，W1 下载后第一时间核对，不能想当然按 16 kHz 写死。
