## 数据、模型与协议

VCTK22 同一 ZIP 中提取 865 个原始 WAV 与 865 份人工转录文本：
p225–p229 各 80 句，其余 15 位注册人各 31 句；20 人每人排序后前 30 句注册。
ZIP 成员 CRC32 与上传后的文件 SHA256 已核对；未下载完整 ZIP，不声称验证整个压缩包摘要。
清单为 `data/VCTK22_subset_manifest.json`；两份注册库各有 `.manifest.json` 记录注册文件摘要。

模型为官方 NTU AdaIN-VC 和固定提交 ECAPA；攻击注册库 `(20,128)`、评估注册库 `(20,192)`。
MOS 使用第三方 `1NEYRON1/mosnet` 固定提交 `4162a3e63ac725ecf7dce8dee3aa71e7afd9c65d`，
与原始 MOSNet/论文权重等价性未验证。Whisper base 权重 SHA256：
`ed3a0b6b1c0edf879ad9b11b1af5a0e6ab5db9205f891f668f8b0e6c6326e34e`。
WER 对照 VCTK 人工文本；原始/保护音频对照目标句，转换音频对照内容源句。

正式选句固定为 p225_040、p226_039、p227_033、p228_035、p229_032；
内容源 p226_002，种子基数 2026，ε=0.05，3000/1500 步。
第二阶段保留上游 c 搜索语义，1500 步可能执行多轮，并非总共仅 4500 步。

这些是单句观测，不能外推批量成功率。完整步数样本的 MOS 预测明显降低、保护音频 WER=40%，
目前没有证据支持论文“强且不可感知”的联合质量结论。主 ASV 使用 ECAPA，
模型、声码器和 MCD 定义均有差异，结果是项目协议的抽样复现。
CUDA 数字是本进程峰值张量分配/缓存，未包含驱动、其他进程或全部 GPU 内存占用。

原始记录路径：`outputs/cloud/{smoke,benchmark}/{manifest.json,results.csv,summary.json,mos.csv,wer.csv}`，
逐句子目录含 5 份 WAV 和 `result.json`。首次计算包含懒加载开销；网页 API 测试在 benchmark 结束后执行。
