## 网络踩坑（重要，供队友参考）

1. **沙箱 shell 无法启动**（0xC0000142）→ 所有命令以非沙箱方式运行。
2. **pip 直连 pypi.org / download.pytorch.org 会卡死**（连接慢，几十分钟零缓存写入），
   而 curl 与 Invoke-RestMethod 正常。
3. 各源实测（curl）：`download.pytorch.org` 快（0.3s）、`pypi.org` 慢（8–10s）、
   `raw.githubusercontent` 超时、清华源超时、阿里源 403（疑似境外出口被 WAF 拦）、
   腾讯源 567、**华为云源可用且快（~3s，pip 实测）**。
4. 结论：
   - 小包 pip 安装：`--index-url https://repo.huaweicloud.com/repository/pypi/simple/`
   - 大文件（torch 2.34GB）：**curl 断点续传**直链下载后本地 pip 安装
   - GitHub 文件：不走 git clone（卡死），走 `api.github.com/git/blobs`（base64）

## 关键发现：ASV 选型分析（重要，实验口径已定）

- **Es 线性探头**（VCTK 20 人训练，val_acc 94.5%）对攻击后的音频过于敏感：攻击损失
  直接移动 Es 特征 → defended 音频立刻被判错（F_imp 失败）。因为探头与攻击在**同一特征空间**。
- 论文的 GE2E 是**独立于 VC 模型**的判别器：扰动在干净音频上不改变判定（99.17%），
  只有经 VC 转换放大后才翻转（12.76%）。对应角色 = **ECAPA**（独立系统）✓。
- 实测 ECAPA 口径下 F_imp/F_str 语义正确：defended 仍判 X ✓、conv(defended) 不判 X ✓
  （exp01 两行 defense_ok=True）。
- **实验口径（最终）**：
  - 攻击期 flag：Es 注册库 argmax（忠实官方代码）；
  - 评估 ASV：ECAPA 为主（对应论文 GE2E 角色），Es 探头为辅（报告双口径）；
  - 筛选协议：按论文剔除 clean-VC 失败的句子，**同时报告筛选通过率**——本环境
    （AdaIN-VC 24k + VCTK22 镜像 + ECAPA）筛选率可能很低，作为局限性如实报告，
    并附未筛选口径的 defense_ok。
