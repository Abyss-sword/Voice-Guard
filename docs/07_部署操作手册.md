# 华为云 GPU ECS 部署与复现实验

## 当前状态（2026-11-04）

用户已购买 GPU ECS，并已使用本机私钥通过 SSH 连接；实际硬件为 Tesla T4、32GB 内存、
100GB 系统盘、Ubuntu 22.04。驱动 580.178.04 已通过 `nvidia-smi` 核验。
云端实验结果与验收状态以 [复现审计](10_复现审计.md) 为准。
代金券适用产品/区域/有效期和实际抵扣比例需在结算页确认，不能把面额视作可用现金余额。

## 1. 创建资源（控制台操作）

从 [华为云官网](https://www.huaweicloud.com/intl/zh-cn/)进入本人账号的控制台。
该国际站链接不代表代金券适用国际站；使用发券账号所属站点。

建议配置：

| 项目 | 建议与核对点 |
|---|---|
| 区域 | 优先查看北京四 cn-north-4；以代金券、GPU 库存和配额为准 |
| 计费 | 按需计费、1 台；结算页核对代金券抵扣及额外现金支出 |
| GPU | NVIDIA CUDA GPU，显存至少 8GB，优先 16GB；如页面提供 T4 可考虑。不要选 Ascend/NPU |
| CPU/内存 | 建议 8 vCPU / 32GB；具体随 GPU 规格选择 |
| 系统 | Ubuntu 22.04 x86_64，优先带适配 NVIDIA 驱动的公共镜像 |
| 磁盘 | 至少 100GB 可用；数据压缩包 10.69GB，解压与 CUDA/Python/镜像还需空间 |
| 网络 | 一个公网 IP，按流量付费的低带宽起步；核对数据下载与公网流量计费 |
| 登录 | SSH 密钥对，本机保留私钥；不要提交进项目或发送密钥内容 |
| 安全组 | TCP 22 只允许本人公网 IP；使用 SSH 隧道访问网页，无需开放 7860 |

若 GPU 无库存或配额为 0，先申请配额或改区域。不要用 CPU 机器承诺完成正式批量攻击。
本轮通过用户在控制台购买资源后提供的 SSH 信息部署；新建其他实例时提供公网 IP、SSH 用户名和本机私钥路径，
即可继续远程执行。用户名以镜像说明为准，常见为 root 或 ubuntu。

预算记录采用结算页实际数值：每小时有效支出约为 ECS + 磁盘 + 公网费用，
先预留至少 20% 余额，完成一条 benchmark 后再按预计总耗时安排实验。
`--max-hours` 只限制脚本运行时间，**不会停止 ECS 或结束云计费**。

## 2. 上传项目（本机 PowerShell）

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\package.ps1
# 替换私钥路径、用户名和公网IP；首次 SSH 应核对控制台显示的主机指纹
scp -i C:\keys\voiceguard.pem outputs\deploy\voiceguard-source.tar.gz ubuntu@公网IP:~/
ssh -i C:\keys\voiceguard.pem ubuntu@公网IP
```

在 ECS 上解包：

```bash
mkdir -p ~/voiceguard
tar -xzf ~/voiceguard-source.tar.gz -C ~/voiceguard
cd ~/voiceguard
bash deploy/ecs_bootstrap.sh
```

脚本核验 `nvidia-smi`，从华为镜像安装系统音频依赖、torch/torchaudio 2.5.1 CUDA 12.4 与固定版本前端栈，
输出 `outputs/cloud/runtime.json`。驱动需支持 CUDA 12.4；失败时先修驱动，不能以 CPU 冒充 GPU 验证。
若当前地域的镜像下载较慢，可用 `VOICEGUARD_PIP_INDEX_URL` 指定其他可信 pip 源。

## 3. 下载资源与构建注册库

推荐在 `tmux new -s voiceguard` 内执行，断开 SSH 后任务继续运行。

```bash
.venv/bin/python scripts/reproduce.py models --max-hours 2
.venv/bin/python scripts/reproduce.py data --max-hours 2
# 抽样复现可改用 data-subset，二者择一：
# .venv/bin/python scripts/reproduce.py data-subset --max-hours 2
.venv/bin/python scripts/reproduce.py registry --max-hours 2
.venv/bin/python tools/preflight.py --scope experiment --out outputs/cloud/preflight.json
```

模型下载器采用官方 NTU AdaIN-VC 权重与固定提交 ECAPA，记录 URL、大小与 SHA256。
AdaIN 配置自动补齐官方 24kHz 预处理参数；VCTK 下载验证镜像提供的 SHA256，
自动整理为 `data/VCTK22/p225/p225_001.wav` 结构。大文件 curl 可断点续传。
没有公布校验值的模型仅记录本地摘要，不能称为已用官方摘要验真。

20 人名单：p225–p234、p236–p241、p243–p246；前 30 句注册，索引 30 起选测试句。
首次正式实验前保存所选文件列表；正式样本不足会报错，不静默缩小分母。
子集下载器保留测试人前 80 句、其他人前 31 句，共 865 句原始 WAV，按文件 CRC32 校验并保存
`data/VCTK22_subset_manifest.json`，同时提取对应的人工转录文本。它不下载全部 110 人，不验证完整 ZIP SHA256；
已有文件仅在长度与 CRC32 均匹配时复用。注册库同时写入 `.manifest.json`，记录实际注册文件的 SHA256。

## 4. 冒烟、测时、正式实验

```bash
# 先查看计划，不下载/加载模型
.venv/bin/python scripts/reproduce.py main --dry-run
# 1 人 × 1 句，60/30 步，只验证执行链路
.venv/bin/python scripts/reproduce.py smoke --max-hours 1
# 三种频域基线各跑 2 步，仅检查梯度/转换/评估链路：
.venv/bin/python scripts/reproduce.py baseline-smoke --max-hours 0.25
# 1 人 × 1 句，3000/1500 步，测正式参数耗时
.venv/bin/python scripts/reproduce.py benchmark --max-hours 2
# 5 人 × 1 句 × 5 方法；根据 benchmark 和实际价格调整时间预算
.venv/bin/python scripts/reproduce.py main --max-hours 2
# 5 人 × 1 句 × 4 ε；独立阶段，余额允许再跑
.venv/bin/python scripts/reproduce.py eps --max-hours 2
.venv/bin/python tools/build_tables.py \
  --exp-dirs outputs/cloud/main_vg,outputs/cloud/main_vg-nop,outputs/cloud/main_emb,outputs/cloud/main_fb,outputs/cloud/main_e2e \
  --out outputs/cloud/results.md
```

默认 2 小时为每次调用上限，超时会中断当前子进程；重新执行同阶段可续跑已完成样本。
每句有独立种子，保存完整 WAV + result.json 才算完成；参数/权重变更时必须换目录。
CSV 同时报未筛选率、clean-VC 通过率和筛选后防御率，不把 clean-VC 已失败的样本算作有效防御。
逐句记录 `elapsed_s` 及 CUDA 峰值分配/保留显存；首句包括模型懒加载开销。
结果目录分开记录 smoke 与 benchmark；冒烟成功不等同于论文结果复现。

上述主表是 **ECAPA 身份维复现**，不是论文全部指标的精确复刻。
Whisper/MOSNet 属额外评测，需安装评测依赖并下载对应权重。
使用 bootstrap 升级后的 pip，安装
`.venv/bin/python -m pip install --build-constraint deploy/evaluation-build-constraints.txt -c deploy/requirements.txt -r deploy/evaluation-requirements.txt`，
再执行 `.venv/bin/python tools/download_models.py mosnet` 可准备固定提交的第三方 MOSNet 模型。
`compute_wer.py` 默认要求 VCTK 文本；原始/被保护音频用目标文本，转换音频用内容源文本。
若镜像缺文本，可明确使用 `--reference-mode whisper`，结果必须标注为伪参考，不能称为真实转录 WER。
论文 ASR_th 与 WER 的映射未被代码充分验证，不将 ASV 成功率标注为联合质量约束成功率。

完成 benchmark 后，可在 tmux 中运行 `bash deploy/run_ecs_campaign.sh`。
它并行执行相互独立的 main/eps 两组（每组默认上限 2 小时），结束后依次运行 MOS/人工文本 WER，
生成 `outputs/cloud/campaign-summary.json` 和 `.md`。可用 `VOICEGUARD_STAGE_MAX_HOURS` 调整每组上限。
主表、ε 扫描和 campaign 日志分别保存在 `outputs/cloud/main.log`、`eps.log`、`campaign.log`。
并行会影响逐句耗时；独立 benchmark 用于设备测时。超时/失败会标记未完成，并保留已完成的句子供重跑。

## 5. 启动界面与验证

在 ECS 的另一个 tmux 会话中：

```bash
cd ~/voiceguard
bash deploy/start_ecs.sh 2>&1 | tee outputs/cloud/service.log
```

也可安装为 systemd 服务：`sudo bash deploy/install_ecs_service.sh`。
该脚本先做实验级预检，随后开机启动；用 `systemctl status voiceguard` 和
`journalctl -u voiceguard -n 100 --no-pager` 检查，用 `sudo systemctl stop voiceguard` 停止网页进程。

在本机另开 PowerShell：

```powershell
ssh -i C:\keys\voiceguard.pem -N -L 7860:127.0.0.1:7860 ubuntu@公网IP
```

打开 `http://127.0.0.1:7860`，选择注册人音频、先用快速模式操作一次，保存原始/保护/转换音频与截图。
保护与转换共享单 GPU 队列；输出采用唯一目录，避免并发覆盖。
网页健康检查 200 只证明 HTTP 可达，还需实际操作与产物验证。

## 7. 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `scp` 上传很慢/中断 | 带宽 5 Mbit/s 太小 | ECS 带宽临时升到 20 Mbit/s；或先传 OBS（控制台拖拽上传），ECS 内 `obsutil cp` 下载 |
| `ssh: connect to host ... timed out` | 安全组没放行 22 / 密码错 | 安全组加 22 入方向；确认用户名 `ubuntu` |
| 页面打不开（浏览器一直转） | 服务没起 / 端口没放行 | `tail -f app.log` 看是否「Running on local URL」；检查安全组 7860 |
| `ValueError: When localhost is not accessible...` | gradio 版本链不对 | 按 §2.5 固定 `gradio 4.44.1 + gradio-client 1.3.0 + fastapi 0.112.4 + starlette 0.37.2 + jinja2 3.1.2` |
| `TemplateResponse` / `unhashable type: dict` | fastapi/starlette 太新 | 同上，`pip install "fastapi==0.112.4" "starlette==0.37.2"` |
| `CUDA out of memory` | GPU 显存不足 | 用 `--device cpu` 或换大显存实例；页面用演示模式 |
| CPU 上保护要十几分钟 | CPU 算力弱 | 用演示快速模式；或提前生成案例 |
| ModelArts 部署失败（拉镜像超时） | 镜像 6–8 GB，冷启动慢 | 等 10–15 分钟；或删镜像中不必要的文件重建（见 Dockerfile 注释） |
| `docker push` 401/403 | 登录指令过期（24h） | 重新生成登录指令再 `docker login` |
| 在线服务 5xx | 健康检查/端口/CMD 配置错 | 端口 7860、路径 `/`、超时 60s；看服务日志 |
