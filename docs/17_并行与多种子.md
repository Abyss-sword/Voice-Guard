# 本地加速与稳健性试点（L6 多种子 / L7 并行）

> 2026-11-09 本地（RTX 4060 8GB）。两项都是工程性试点，用于指导云端批量实验的
> 耗时预算与方差报告；不作为论文结论。

## L7：多进程并行（按说话人拆分）

**背景**：单句攻击的 CUDA 峰值仅 ~175MB（T4 实测），4060 也远未用满；单进程攻击是
"小算子串行延迟"型负载，多进程可并行占用 GPU 执行队列。

**实现**：`scripts/run_parallel.py`——把说话人列表轮流分给 K 个 worker，每个 worker 是
独立的 `run_experiment.py` 子进程，结束后汇总 `parallel_summary.json`。

**实测**（3 句、200/100 步、同一台 4060）：

| 方式 | 耗时 | 相对 |
|---|---:|---:|
| 串行（1 进程） | 79.8 s | 1.00× |
| 并行（3 worker） | **36.7 s** | **2.17×** |

**建议**：云端批量实验（主表 9 组、ε 扫描、多种子）可用 `--workers 2~4`
（按显存与句长调整）；worker 数超过显存/带宽时收益递减，需实测。

```powershell
.\.venv\Scripts\python.exe scripts\run_parallel.py --workers 3 `
  --speakers p225,p226,p227,p228,p229 --per-speaker 1 --iters1 3000 --iters2 1500 `
  --out-root outputs/parallel_main
```

## L6：多种子小表（每句独立种子）

**背景**：项目为每句派生独立种子（不依赖执行顺序），但历史上每句只跑一次；
本试点用 2 个种子跑同一批 3 句，观察判定与指标波动。

**结果**（3 句 × 2 seed，200/100 步，ε=0.05，ECAPA 口径）：

| 句子 | seed 2026 | seed 2027 |
|---|---|---|
| p225_040 | 防御成功 | 防御成功 |
| p226_039 | 失败 | 失败 |
| p227_033 | 防御成功 | 防御成功 |
| **合计** | **2/3** | **2/3** |
| MCD（均值±std） | 38.5±3.5 | 38.5±3.5 |

**结论（如实）**：该预算下两个种子给出**完全相同的判定与几乎相同的 MCD**——
说明当前实现的种子敏感度低（初始化差异很快被优化吸收），但也说明单次运行不足以
估计方差；更大规模（云端 3000/1500 步 × ≥10 句 × 2–3 seed）才能给出有意义的
mean±std 与显著性判断。

产物：`outputs/parallel_test/seed2026|seed2027/results.csv`、
`outputs/parallel_test/multiseed_summary.json`。

## L8：前端质量模式与实时进度

- **质量模式**：前端「方法」下拉已有 `vg-projected`（refine 1000 步）；本项补充**实时进度条**。
- **实现**：`vguard/attack.py` 的阶段1/2 增加 `progress_cb(fraction, desc)`（按迭代 1/20 步回调）；
  `vguard/pipeline.py::protect(..., progress_cb=)` 透传；前端 `on_protect` 用
  `gr.Progress(track_tqdm=False)` + 线程池轮询回调更新进度条。
- **验证**：60/40 步保护触发 **100 次回调，0.03 → 1.00**，前端构建 56 组件通过。
- 效果：长任务（3000/1500 步，30–90 秒以上）不再"假死"，可看到 `stage1` / `stage2(c=..)` 进度。

## C12：长音频工程验证

- 把 3 句 VCTK 拼接成 **10.88s** 音频，`scripts/protect.py`（300/200 步）完整跑通：
  **elapsed 40.3s**，显存正常，产物齐全（defended/delta/conv 等）。
- 该预算下身份维度判定失败（`defense_ok=false`，保护后 p225 sim 0.667）——符合
  短步数的预期；正式 3000/1500 步需更长时间。结论：**管线对 10s 级长音频可用**，
  云端可放心跑更长样本（`--max-dur 0` 时按 trim 后全长处理）。
