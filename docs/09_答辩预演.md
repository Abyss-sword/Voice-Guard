# 答辩预演：预测问题与应答要点（9 分钟展示后 Q&A）

## 方法类

**Q1：为什么扰动放在时域而不是频域？**
A：频域（mel）扰动必须经声码器上采样回波形（Attack-VC 的做法），这一跨域转换是有损的，
扰动能量被稀释；时域直接改波形，梯度经可微 mel 提取器 H 一路反传（H 是我们重写的
STFT+mel+log 链），扰动逐样本精确到位。实测：频域基线防御率 25% vs 时域 75%。

**Q2：可微 H 和 librosa 有什么差别？会不会有数值误差？**
A：实现上是同一公式链（preemph→STFT→mel→log→clip→标准化），PyTorch 版可求导。
我们对齐测试：与官方 numpy 预处理逐点误差 ≤1e-4（float32 精度），tests/test_features.py 全过。

**Q3：掩蔽阈值 θx 怎么算的？怎么保证扰动"听不见"？**
A：按论文附录 A：先找掩蔽者（帧内能量峰值），双斜率扩散函数合成全局掩蔽阈；
扰动 PSD 与 θx 归一化到同一 96 dB 尺度，损失 hinge mean(ReLU(PSD_δ−θx)) 把噪声压到阈下。
诚实说明：这是软约束，ε 大时压不住——我们验证了 ε 依赖（ε=0.01 时 loss_th 收敛到 ~5dB，
ε=0.1 时 ~30dB 下不去）。

**Q4：c 二分搜索为什么常停在 8？**
A：攻击期身份判定用官方 Es-argmax，20 人闭集下判别力弱，flag 几乎恒 True → c 一路乘 2。
这是官方代码的忠实行为，我们如实报告，并把强判别交给评估侧（ECAPA）。

## 实验类

**Q5：防御率 75% 是怎么算出来的？样本量这么小可靠吗？**
A：按论文协议：剔除 clean-VC 失败的句子后，F_imp∧F_str 都满足才算成功。
5 句 × 4 档 ε = 20 个攻击点（另有 exp01/02 的 10 句、频域基线 15 句、EOT 5 句），
每个点 20-60 分钟 GPU 优化。抽样规模小于论文（时间与算力限制，如实声明），
但方法间对比在同一批句子上做控制变量，相对结论稳健。

**Q6：论文说 ASV(defended) 99% 不变、转换后 12.8% 变，你们的数字为什么不同？**
A：三处环境差异：① 评估 ASV 不同（论文 GE2E 是 VCTK 训练的原生判别器，我们用
VoxCeleb 域的 ECAPA——更严格，clean-VC 筛选率都受影响）；② VC 权重不同
（官方 AdaIN-VC vs 论文的 attack-vc 改版）；③ 数据 22kHz 镜像 vs 48kHz 原版。
绝对数字不可比，但**趋势复现**（时域≫频域、ε 权衡曲线形态、F_imp/F_str 分解结构）。

**Q7：ε=0.05 时掩蔽项没用？那论文的贡献怎么体现？**
A：在二元防御率和 MOS 上确实没体现（0.05 的噪声已远超阈值），但掩蔽改变的是噪声的
频谱结构（能量集中在高掩蔽阈频带——fig_masking.png 可见），且在更小 ε（论文工作点）
和更大迭代预算下才收敛（ε=0.1@3000/1500 步 MOS 2.0 vs 800/400 步 0.8）。
这是对论文"强且不可感知"工作点更细致的刻画。

## 加分项类

**Q8：EOT 为什么让防御变差了？这算失败吗？**
A：我实现的 EOT 是攻击侧稳健性（约束扰动过信道后仍能翻转转换），等于给攻击者
更强扰动 → F_imp 受损 → 净防御率下降（G.711 上 60%→20%）。这是**受控的负面结果**：
它精确回答了"信道稳健化应该加在哪一侧"——正确做法是把 F_imp 放进损失
（min_δ [攻击项+掩蔽项+F_imp-信道项]）。方法论上这是比"报喜"更有价值的产出。

**Q9：真实信道到底会不会破坏防御？**
A：数据说话：mp3/aac 几乎无影响（转换相似度 ~0.107 不变）；8k/G.711 双向分化
（部分句子攻击被削弱 2.4×，部分句子防御反而更强）；真正的薄弱环是 F_imp
（defended 自身相似度降最多 0.16）。所以答案不是简单的"会/不会"，而是"取决于
信道类型与句子"——这个异质性本身是发现。

## 工程类

**Q10：系统怎么跑？部署呢？**
A：Gradio 三页签前端（上传→保护→试听/下载），本地 http://127.0.0.1:7860 实测；
**已在华为云 Tesla T4 ECS 真实部署**（systemd 服务 + SSH 隧道 HTTP 200，真实 `/on_protect`
调用验证，证据 docs/11 与 docs/evidence/2026-11-04/）。Docker/ModelArts 为备选路线，
步骤在 docs/07。权重与注册库经 GitHub Release + 百度/迅雷/夸克云盘分发（含 SHA256）。

**Q11：代码能一键复现吗？**
A：能。README 给出完整命令链（权重 curl/云盘 → 注册库 → 保护/批量 → 评估 → 前端）；
云端用 `scripts/reproduce.py` 分阶段（models→data→registry→smoke→benchmark→main→eps），
manifest 记录参数与权重摘要、结果原子写入可续跑。网络受限环境的依赖安装用 tools/ 的
curl+本地 wheel 方案，版本链已 pin 死。

**Q12（新增）：为什么保护后 MOS 反而下降？论文不是说"不可感知"吗？**
A：这是本环境最关键的诚实结论：身份维（ECAPA）判定通过，但 MOSNet 预测从 3.33 降到
1.02、WER 升到 40%——**未复现论文"强且不可感知"的联合质量**。原因：我们的 ε=0.05
噪声幅度已远超掩蔽阈（软约束压不住）、评估系统（ECAPA/MOSNet/22kHz 数据）与论文不同。
我们如实记录，并做了改进探索（见 Q13）。

**Q13（新增）：refine 是什么？**
A：为修复"身份通过但质量差"，我们加了**掩蔽投影后继续优化**：在原始 VG 输出上每步把
扰动 STFT 幅度投影到 θx 下、峰值限幅 2ε、再继续 1000 步优化。平均 MOS 1.397→3.192、
平均逐句 WER 62.76%→5.71%，固定参数验证联合通过 1/2（筛选后）。但仍是小样本、投影
非严格不可感知（约 0.7% 时频格超阈），属工程探索而非论文复现。

**Q14（新增）：为什么 T4 上这么快（194s/句）？**
A：本机 4060 笔记本 4.3s 句约 40 分钟，云端 T4 2.2s 句 194 秒——差距来自三方面：
句子更短（2.2s vs 4.3s）、T4 算力更强、以及完整的 3000/1500 步预算下实测就是这个量级。
显存峰值仅 ~200MiB，说明瓶颈在串行计算而非显存——这也提示可以用 batch 并行进一步提速。
