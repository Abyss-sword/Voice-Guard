# 质量改进实验（2026-11-04）

在华为云 Tesla T4 上，新增“掩蔽投影后继续优化”的实验方法。相同 5 句的保护音频平均
MOSNet 预测从原始 VG 的 **1.397 提升至 3.192**，逐句 WER 的算术平均从 **62.76% 降至 5.71%**。
PCM16 导出验证中，p225、p228 同时保留原说话人身份、改变转换后身份，且 MOS≥3、WER≤10%。
**仍未达到可宣称复现论文质量的程度**：论文白盒 VG 报告保护音频 MOS 4.07、WER 7.84%，
其模型、数据、评价系统与本项目不同。这里的预测分数不能直接等同论文或人工听感。

## 协议与参数

沿用云端主实验固定选句 p225_040、p226_039、p227_033、p228_035、p229_032，内容源 p226_002，
20 人注册库、官方 NTU AdaIN-VC、ECAPA、第三方 MOSNet、Whisper base 与人工文本参考。
原始 VG 使用 ε=0.05、3000/1500 步；本轮在其输出上进行额外优化。
这里比较的是 `outputs/cloud/main_vg`，不是之前独立运行的单句 benchmark。

先用 p225、p226 开发，再固定 1000 步、Adam lr=0.0003、掩蔽余量 3dB，在 p227、p228、p229
验证；[固定配置](evidence/2026-11-04/quality/frozen_refinement_profile.json) 保存了参数与算法摘要。
每步限制扰动的 STFT 幅度并重建波形，扰动峰值限制为 2ε；初始化、结束各额外投影 30 次。
损失仍为原来的说话人编码器目标：接近另一人的嵌入，并远离原人的嵌入。
MOSNet、Whisper、ECAPA 均未加入优化损失。
额外优化每句约 21–26 秒，包含与主实验并行时的资源竞争，不是独占 GPU 速度。

工程联合门槛：保护音频 MOS≥3、人工文本 WER≤0.10、ECAPA 仍判为原说话人，且转换后不再判为原说话人。
必须另用 scale=0 测得干净转换身份正确，否则排除该句的防护统计。
论文 ASR 阈值与 WER 的映射不明确，因此此门槛是本项目的工程代理，不能称为论文 Eq.9/10 的精确实现。

## 逐句结果：实际 PCM16 导出后重新评估

| 句子 | 原始 VG MOS | 改进 MOS | 原始 VG WER | 改进 WER | 保护 / 转换后身份 | 筛选后联合门槛 |
|---|---:|---:|---:|---:|---|---|
| p225_040（开发） | 1.049 | 3.275 | 40.00% | 0 | p225 / p246 | 通过 |
| p226_039（开发） | 0.519 | 3.165 | 100.00% | 0 | p226 / p226 | 未改变转换身份 |
| p227_033（验证） | 2.313 | 3.153 | 57.14% | 28.57% | p227 / p227 | 内容与防护均未通过 |
| p228_035（验证） | 0.673 | 3.409 | 66.67% | 0 | p228 / p226 | 通过 |
| p229_032（验证） | 2.432 | 2.958 | 50.00% | 0 | p229 / p231 | MOS 未通过；干净转换已错判，排除 |

全部 5 句保留在质量均值中，未只取成功样例。开发集联合通过 1/2；固定参数验证集 3 句中，
2 句满足干净转换身份筛选，联合通过 **1/2**。两组合计 2/4，只是小样本观测，不能外推总体成功率。
原始 VG 同 5 句没有同时通过上述质量门槛的样本。
WER 为逐句比例的算术平均，不是合并全部单词后计算的语料 WER；原始 CSV 数值保留四位小数。

FLOAT 与 PCM16 两种导出均在 p225、p228 保留联合通过。p225 的转换身份从 FLOAT 的 p230 变为 PCM16 的
p246，说明具体错分标签敏感；PCM16 中最强错误身份相对原身份的余弦分数差为 0.03085，p228 为 0.15462。
这只验证了本次量化导出，没有验证压缩、重采样或真实麦克风信道稳健性。

最终生成脚本还独立重跑了一次 p225（相同参数与种子），PCM16 评估为 MOS=3.280、WER=0，
保护身份 p225、转换身份 p246，联合门槛再次通过。两次优化波形的 SHA256 不同，最大绝对差 0.01367、
差值 RMS 0.001279；未强制确定性 CUDA 运算，不能承诺逐位重现。这一次重复也不能替代多种子稳定性实验。
原始两组结果不被重跑结果替换；见 [独立重跑检查](evidence/2026-11-04/quality/replay-check.json)。

STFT 投影也不是严格不可感知性证明：PCM16 的两个通过样例仍分别有约 0.694%、0.621% 的时频格
高于掩蔽阈值，平均正超额约 0.0207、0.0149dB，SNR 约 14dB。没有开展人工听测。

## 保留失败探索与完整音频诊断

| 实验目录 | 内容 | 观测 |
|---|---|---|
| `dev_scale_eps002` | p225/p226，ε=.02 原始 VG 扰动按 0/.05/.1/.2/.4/.7/1 缩放 | 小扰动恢复质量，但无联合通过 |
| `dev_project_eps005` | p225/p226，30 次谱投影、3dB 余量 | MOS 约 3.31/3.11，WER 均 0，但防护丢失 |
| `refine_dev_eval` / `refine_validation_eval` | 投影后继续优化；FLOAT 导出 | 分别联合通过 1/2、1/2（筛选后） |
| `refine_dev_pcm16_eval` / `refine_validation_pcm16_eval` | 同一优化产物导出 PCM16 | 两个联合通过样例保留 |
| `refine_dev_context_eval` / `refine_validation_context_eval` | 保留完整原音，只在原裁剪区间叠加扰动 | 开发 p225 通过；验证集无联合通过 |

完整音频诊断在上述固定参数验证后追加，不能回溯描述为原验证协议。它暴露两个问题：

- p227 原始 `top_db=15` 裁剪已丢掉较轻的 “It is”，零扰动 WER 就是 28.57%。保留上下文后原音与保护音频
  WER 均为 0，但保护音频 MOS 仅 2.591，转换身份仍为 p227。
- p228 完整原音的干净转换已判为 p231，保护后同样判为 p231，必须从该协议的防护统计中排除。
  p229 同样排除。MOSNet 对完整音频（包含静音/低声部分）的分数也明显变化，不应通过切换裁剪口径选择更好分数。

完整音频版本 p225 MOS=3.145、WER=0，干净转换 p225、保护后转换 p246；这是单个开发样例。
11 月 4 日时仅通过独立实验脚本调用；11 月 9 日已将投影优化和完整上下文作为 Gradio/课程平台的可选参数接入并实际调用验证。原始 VG 仍为默认方法，上下文默认关闭，不将不同处理协议混入原基线。

## 11 月 9 日扩展验证

事前冻结的新 10 句中，原法/改进 MOSNet 为 1.936/3.055，宏平均 WER 为 44.60%/14.69%，
但两者联合通过均为 0/8。改进中有 3 句在干净控制成立时达到保护质量门槛，转换身份却仍为目标。
首批五句的局部联合改善没有迁移为本次新句上的联合成功，不根据验证失败重新调参。

8 信道 80 次、3 内容源 60 次配对已完成。p225 在 MP3 128 kbps 下出现质量仍过关但身份防护丢失，
而 32 kbps 下保留，不能宣称码率越低防护必然越差。G.711/8 kHz 使原样成功样本的干净控制失效，须与防护丢失区分。

完整上下文事后诊断把新句保护 WER 降至 3.10%，但 MOSNet 为 2.884、联合 0/7；没有形成完整解决方案。
同 WAV 的默认/固定温度 ASR 控制还确认解码随机性会影响噪声语音 WER，未用较低的新分数覆盖原冻结结果。
全部逐句表、原因分析和独立边界见 [当前报告](04_报告.md)。

## 重跑

在已部署资源齐备的 ECS `/root/voiceguard` 中运行，结果目录须使用新名称。
脚本会拒绝参数、输入、代码或完整产物摘要发生变化的续跑；历史实验早期脚本版本与当前版本摘要不同。

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
# 已有 outputs/cloud/main_vg 时可从此处开始；否则先执行主实验。
.venv/bin/python scripts/refine_masked.py \
  --exp-dir outputs/cloud/main_vg --out-dir outputs/quality/repeat_dev \
  --speakers p225,p226 --steps 1000 --learning-rate .0003 --margin-db 3
.venv/bin/python scripts/quality_sweep.py \
  --exp-dir outputs/quality/repeat_dev --out-dir outputs/quality/repeat_dev_eval \
  --speakers p225,p226 --scales 0,1 --wav-subtype PCM_16
cp outputs/quality/repeat_dev/manifest.json outputs/quality/repeat_frozen_profile.json
.venv/bin/python scripts/refine_masked.py \
  --exp-dir outputs/cloud/main_vg --out-dir outputs/quality/repeat_validation \
  --speakers p227,p228,p229 --steps 1000 --learning-rate .0003 --margin-db 3
.venv/bin/python scripts/quality_sweep.py \
  --exp-dir outputs/quality/repeat_validation --out-dir outputs/quality/repeat_validation_eval \
  --speakers p227,p228,p229 --scales 0,1 --wav-subtype PCM_16
# 完整音频诊断：另选输出目录，并添加 --restore-context。
```

每句 `optimization.json` 只表示优化完成（`evaluated:false`），不伪装成已完成转换与独立评估的主实验结果。
质量脚本从实际写出的 WAV 重读后计算指标；`summary.json/results.csv` 在全部零扰动控制齐全后记录筛选标志。
原始逐句 JSON、完整假设文本、音频 SHA256、各身份余弦分数和全部失败探索，见
[文本证据目录](evidence/2026-11-04/quality/README.md)。音频已备份在本机和云端，未提交数据集音频/模型/密钥。

不需要模型即可重建上表：

```bash
python tools/build_quality_report.py
```
